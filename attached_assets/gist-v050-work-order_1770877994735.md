## What's Working in v0.4.0

These are solid — preserve them, don't regress.

- Thread replies: `POST /api/g/:slug/threads/:threadId/reply` endpoint, JSONB messages array, full reply UI on viewer + editor
- Auto-save: 2-second debounce with "saving/saved" status indicator
- Self-hosted fonts: Inter + JetBrains Mono WOFF2 in `client/public/fonts/`, @font-face declarations, no CDN
- Type scale: `.type-h1` through `.type-meta-emphasis` utility classes in index.css
- Dark mode: `darkMode: "media"` in Tailwind config, full CSS variable overrides for light + dark
- Shadow tokens: `--shadow-subtle`, `--shadow-medium`, `--shadow-prominent` (warm-ink rgba), mapped to Tailwind `shadow-subtle` / `shadow-medium` / `shadow-prominent`. Dark mode sets all to `none`.
- Access control: Three-tier system (open/verified/restricted) with OTP gate component and backend enforcement
- Brand mark: Inline SVG GistLogo component using CSS variables, renders in nav across all pages
- Primitive blocks: Decision, Thread, Timeline, Snapshot — all rendering with left-border, labels, metadata
- Content width: `.content-width` utility (680px max) defined and used
- Synthesis panel: Above the fold on viewer, 4 tabs, streaming SSE, token tracking
- Business model: 1 free Gist, 20 synthesis tokens, upgrade prompt on dashboard
- Export: `.md` export from viewer, includes frontmatter

### Deliverable 1: Button Refinement

The default (filled) button variant applies `border border-primary-border`, where `--primary-border` uses a relative color calculation that creates a visible darker ring around the teal fill. On small buttons this looks beveled and cheap.

**Changes to `client/src/components/ui/button.tsx`:**

1. Default variant: change `border border-primary-border` to `border border-transparent`
   ```typescript
   // CHANGE THIS:
   default: "bg-primary text-primary-foreground border border-primary-border",
   // TO THIS:
   default: "bg-primary text-primary-foreground border border-transparent",
   ```
   The filled teal has sufficient contrast against the cream canvas without a visible border. The transparent border preserves layout sizing.

2. Keep the outline variant as-is — its `[border-color:var(--button-outline)]` (10% black) is correct for secondary actions.

3. Keep the ghost variant as-is.

**Do NOT** change border-radius. `rounded-md` (6px) matches our `interactive` token. The shape is correct — it's the border that creates the perceived stiffness.

**Test by:**
- Compare "Get started" and "Dashboard" buttons before and after
- The teal fill should feel cleaner without the darker edge
- Verify ghost, outline, and destructive variants are unaffected

### Deliverable 2: Landing Page Polish

Several small adjustments to the landing page (`client/src/pages/landing.tsx`).

**Icon colors — unify to `var(--ink-secondary)`:**

All six feature card icons should use the same color. The primitive-specific colors (decision teal, thread gray, timeline tan) belong on actual rendered blocks inside the product, not on marketing cards. Uniform icons let the text differentiate.

```typescript
// CHANGE: each feature object's color property
// FROM: different colors per card
// TO: all the same
color: "var(--ink-secondary)",
```

Apply this to all 6 feature objects in the array.

**Feature card text — use `type-body`:**

Card descriptions currently use `text-[14px]` (one pixel below our body spec). Change to the type scale utility:

```tsx
// CHANGE THIS:
<p className="text-[14px] leading-[1.6]" style={{ color: "var(--ink-secondary)" }}>
// TO THIS:
<p className="type-body">
```

The `type-body` class already sets 15px, 400 weight, 1.65 line-height, and `var(--ink-secondary)` color.

**Feature cards — shadows instead of borders:**

Cards currently use `border: 1px solid var(--gist-border)`. Replace with shadow:

```tsx
// CHANGE THIS:
style={{
  backgroundColor: "var(--canvas-raised)",
  border: "1px solid var(--gist-border)",
}}
// TO THIS:
className="p-5 rounded-structural shadow-subtle hover:shadow-medium transition-shadow duration-150"
style={{ backgroundColor: "var(--canvas-raised)" }}
```

The hover shadow gives the page texture without the cards being clickable.

**Hero headline — increase size for landing page only:**

The `type-h1` scale (28px) is correct for in-app page titles. The landing page hero can be larger. Apply a one-off style:

```tsx
// CHANGE THIS:
<h1 className="type-h1 mb-4">
// TO THIS:
<h1 className="mb-4" style={{
  fontSize: "36px",
  fontWeight: 600,
  lineHeight: 1.2,
  letterSpacing: "-0.03em",
  color: "var(--ink-primary)",
}}>
```

### Deliverable 3: Abstract the Frontmatter from the Editor

The editor currently shows raw YAML frontmatter (`---`, `title: Test Gist 1`, `updated: 2026-02-12`, `---`) as editable text in CodeMirror. This is an implementation detail the user should never see or accidentally break.

**Changes to `client/src/pages/editor.tsx`:**

1. On gist load, parse the YAML frontmatter and extract `title` and `updated` into state. Strip the frontmatter from what gets passed to CodeMirror.

2. Render a proper title bar ABOVE the CodeMirror editor:
   ```
   ┌──────────────────────────────────────────────────────────────┐
   │ [← Back]  [editable title input]         [Auto-save status] │
   │           Updated 2 minutes ago                             │
   ├──────────────────────────────────────────────────────────────┤
   │ CodeMirror editor (body content only — no --- fences)       │
   ```

3. The title input: a plain text field styled as `type-h1` (28px, 600 weight, -0.02em letter-spacing). No border, no background — just looks like a heading you can click into and edit. Editing it updates React state, not the raw markdown.

4. Strip the frontmatter block (everything between the first `---` and the second `---`, inclusive) from the string passed to CodeMirror. The editor should only show body content.

5. On save (both auto-save and manual), reconstruct the full .md by prepending the YAML frontmatter with the current `title` and today's date to the CodeMirror body content. The existing frontmatter reconstruction logic on lines 62-66 already does this — just ensure it uses the state-managed title rather than parsing the editor content.

6. Display the `updated` timestamp as relative time ("Updated 2 minutes ago") in `type-meta` styling.

**Do NOT:**
- Change the .md format stored on the server — frontmatter is still part of the canonical file
- Change the export format — exported .md still includes frontmatter
- Remove the ability to have frontmatter — just hide it from the editing surface

### Deliverable 4: Editor Mobile Layout

The 50/50 split editor is unusable on mobile. On screens < 640px, switch to a single-pane view with a toggle.

**Changes to `client/src/pages/editor.tsx`:**

1. Use the existing `useIsMobile()` hook from `use-mobile.tsx`

2. On mobile, replace the side-by-side layout with:
   ```tsx
   {isMobile ? (
     <div className="flex flex-col h-full">
       <div className="flex border-b" style={{ borderColor: "var(--gist-border)" }}>
         <button
           onClick={() => setMobileView('edit')}
           className={`flex-1 py-2 text-sm font-medium ${mobileView === 'edit' ? 'border-b-2' : ''}`}
           style={mobileView === 'edit' ? { borderColor: "var(--gist-accent)", color: "var(--ink-primary)" } : { color: "var(--ink-tertiary)" }}
         >
           Edit
         </button>
         <button
           onClick={() => setMobileView('preview')}
           className={`flex-1 py-2 text-sm font-medium ${mobileView === 'preview' ? 'border-b-2' : ''}`}
           style={mobileView === 'preview' ? { borderColor: "var(--gist-accent)", color: "var(--ink-primary)" } : { color: "var(--ink-tertiary)" }}
         >
           Preview
         </button>
       </div>
       {mobileView === 'edit' ? <GistEditor ... /> : <MarkdownRenderer ... />}
     </div>
   ) : (
     /* existing 50/50 split */
   )}
   ```

3. The thread panel on mobile should be accessible via a "Threads" tab alongside Edit and Preview, or via a bottom sheet.

4. Toolbar actions (Add Decision, Add Thread, etc.) should collapse into a single "+" menu on mobile.
