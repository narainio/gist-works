# Shared Context Surface — Design System

**Version:** 1.0
**Date:** 2026-02-11
**Stage:** Design (4/7)

**Philosophy:** Warm Signal. Sharp information hierarchy on a crafted, warm surface with subtle primitive differentiation. Everything you need, nothing you don't — but it has a pulse. The product makes you feel like you've got this.

---

## 1. Identity

**Brand keywords:** Confident, Crafted, Quiet, Signal, Warm

**Design direction:** Warm Signal

**Rationale:** Foundation of Signal Clarity (Direction 2) — razor-sharp hierarchy, information density that never overwhelms, designed for someone who works fast. Warmth from Quiet Confidence (Direction 1) — warm canvas, humanist typography, craft visible without competing for attention. Primitive layering from Living Surface (Direction 3) — subtle left-border differentiation so you can scan and distinguish document spine from decisions, threads, timeline, and snapshots at a glance. Reference products: Withings Scanwatch Light (exactly what you want, nothing you don't, discreet and elegant), Raycast clipboard (always there, easy to find, paste it anywhere), Google Search (frictionless, portable, trustworthy), Session Zero (gets out of the way). The design expresses "quiet confidence" — the outcomes speak for themselves.

**Anti-patterns (never do this):**
- Never compete with content for attention
- Never add visual complexity for its own sake
- Never use decoration where information should be
- Never animate to "delight" — animate only to acknowledge or orient
- Never require explanation — if a UI element needs a tooltip, reconsider the element

### Usage Rules

- Accent color is interactive — if it's `accent`, it must be clickable or signal a structured decision
- No gradients. Flat fills only.
- Primitive borders are always left-border, 3px width
- Surface colors are always warm — never use pure #FFFFFF as a background in light mode, never use pure #000000 in dark mode
- Color alone never carries meaning — always pair with text labels or icons

## 3. Typography

### Font Stack

| Layer | Font | Fallback | Usage |
|-------|------|----------|-------|
| UI | Inter | -apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif | Interface, buttons, labels, headings |
| Content | Inter | Same as UI | Long-form content, body text, descriptions |
| Code | JetBrains Mono | 'SF Mono', 'Cascadia Code', 'Fira Code', monospace | Structured data, metadata, decision IDs, timestamps, code blocks |

### Type Scale

| Element | Size | Weight | Line Height | Letter Spacing |
|---------|------|--------|-------------|----------------|
| H1 | 28px | 600 | 1.3 | -0.02em |
| H2 | 22px | 600 | 1.35 | -0.01em |
| H3 | 18px | 600 | 1.4 | -0.01em |
| Body | 15px | 400 | 1.65 | 0 |
| Small / Caption | 13px | 400 | 1.5 | 0 |
| Primitive label | 11px | 600 | 1.4 | 0.05em (uppercase) |
| Code / Meta | 13px | 400 | 1.6 | 0 |
| Meta emphasis | 12px | 500 | 1.5 | 0 |

### Typography Rules

- Headings use negative letter-spacing for tightness at large sizes
- Primitive labels (DECISION, THREAD, TIMELINE, SNAPSHOT) are always uppercase, 11px, weight 600, with wide letter-spacing — they signal structure
- Body text at 15px/1.65 is optimized for reading at content width (max ~680px)
- Monospace (JetBrains Mono) signals "this is structured information" — timestamps, contributor counts, IDs, metadata
- Never bold body text for emphasis — use `ink-primary` weight 500 if emphasis is needed, or restructure the information hierarchy

**Base unit:** 4px

| Token | Value | Usage |
|-------|-------|-------|
| `space-xs` | 4px | Tight padding, inline element gaps, icon-to-label |
| `space-sm` | 8px | Compact element spacing, padding inside tags/badges |
| `space-md` | 16px | Standard element spacing, card internal padding, left-border block padding-left |
| `space-lg` | 24px | Section gaps within a card, spacing between primitive blocks |
| `space-xl` | 32px | Major section breaks, card-to-card spacing |
| `space-2xl` | 48px | Page-level section spacing |

**Content width:** Max 680px for reading content. Sidebar (navigation, meta) is secondary, max 280px.

**Border radius:**

## 5. Components

### Core Components (MVP)

| Component | Description | Key Tokens | Interaction |
|-----------|-------------|------------|-------------|
| **Context Surface** | The main artifact view — the canonical spine rendered with all primitives | `canvas`, `canvas-raised`, full type scale | Scrollable, sections collapsible |
| **Primitive: Decision** | Left-bordered block with structured decision content (question → options → evidence → conclusion → rationale) | `primitive-decision` border, `accent` for label, `ink-primary` for content | Collapsible. Label reads "DECISION" in accent color. Shows participants. |
| **Primitive: Thread** | Left-bordered block containing ingested or native discussion | `primitive-thread` border, `ink-tertiary` for label, `ink-secondary` for content | Collapsible. Shows contributor names in `ink-primary`. Source indicator (Slack/WhatsApp/native). |
| **Primitive: Timeline** | Left-bordered block with chronological entries | `primitive-timeline` border, code font for dates, `ink-secondary` for entries | Expandable entries. Dates in monospace. |
| **Primitive: Snapshot** | Left-bordered block with non-text artifact references | `primitive-snapshot` border, link arrow (↗), `ink-tertiary` for metadata | Click opens snapshot. Shows capture timestamp in monospace. |
| **Synthesis Panel** | AI-generated view/summary — the context synthesis output | `canvas-raised` surface, `accent-subtle` top border or background | Regenerable. Shows "Synthesized [timestamp]" in monospace. View type selector (executive summary / full context / decisions only / what changed). |
| **Contributor Badge** | Person identifier with name and optional avatar | `ink-primary` for name, `ink-tertiary` for role/org | No avatar required (zero identity tax). Name + org is sufficient. |
| **Action Button (Primary)** | Primary action — "View synthesis", "Share", "Copy link" | `accent` background, #FFFFFF text, 6px radius | Hover: `accent-hover`. Active: darken 10%. No loading spinners — snap response. |
| **Action Button (Secondary)** | Secondary action — "Collapse all", "Filter", "Export" | `border` border, `ink-primary` text, transparent background | Hover: `canvas-raised` background. |
| **Tag / Badge** | Primitive type indicators, status markers, source indicators | `accent` for decision tags, `ink-tertiary` for metadata tags, pill radius | Static. No interaction unless filterable. |
| **Meta Line** | Compact metadata row — contributor count, last updated, thread count | Code font, `ink-tertiary`, `space-xs` gaps | Static information. |
| **Share Link** | Zero-identity-tax access link with permissions indicator | `accent` for link, `ink-tertiary` for permission label | Click copies. Shows "Copied" confirmation (100ms snap). |

### Primitive Block Structure (shared across all primitives)

```
┌─────────────────────────────────────────┐
│ ▌ LABEL (uppercase, 11px, colored)       │
│ ▌                                        │
│ ▌ Content (15px body or 13px code)       │
│ ▌                                        │
│ ▌ Meta line (12px mono, ink-tertiary)    │
└─────────────────────────────────────────┘
  ↑
  3px left border in primitive color
  16px padding-left
```

All primitive blocks share this structure. The left-border color and label text distinguish them. This consistency is intentional — you learn the pattern once, then scan by border color.

## 6. Motion & Interaction

**Default durations:**
- Micro interactions (button press, copy confirmation): 100ms
- Layout transitions (collapse/expand, panel reveal): 150ms
- Content fade (synthesis loading, view switching): 150ms

**Easing:**
- Entrances: ease-out (fast start, gentle stop)
- Exits: ease-in (gentle start, fast end)
- State changes: ease-out

**Principles:**
- Snap, don't slide. Things appear and disappear. No traveling animations.
- Acknowledge immediately. Button presses show response in <100ms. If something takes longer, show the result state instantly and populate content as it arrives.
- No bounce, no spring, no overshoot. Confidence is still, not bouncy.
- Collapse/expand is the primary motion — primitives collapse to their label line and expand to full content. This is the only "animation" the user sees regularly.
- Loading states: content area shows immediately at full height with `canvas` background. Content populates without layout shift. No skeleton screens, no spinners, no shimmer.

## 7. Responsive

| Breakpoint | Width | Key Adaptations |
|------------|-------|-----------------|
| Mobile | < 640px | Single column. Full-width primitives. Navigation via top bar, no sidebar. `space-2xl` page margins reduce to `space-lg`. Content width = 100% minus margins. |
| Tablet | 640–1024px | Reading-width content centered. Sidebar collapses to overlay. Comfortable margins (`space-2xl`). |
| Desktop | > 1024px | Content column max 680px + optional sidebar (280px) for navigation/meta. Generous margins. |

**Minimum touch target:** 44px × 44px for all interactive elements

**Responsive principles:**
- Content readability is the priority at every breakpoint — never sacrifice line length or type size for layout
- Primitives stack vertically at all breakpoints — no side-by-side primitive blocks
- Sidebar content (navigation, meta, contributor list) moves to top bar or collapsible panel on mobile
- Share link and primary actions are always visible without scrolling

## 8. Dark Mode

**Strategy:** Automatic (OS preference) with no manual toggle in V1. The product respects the user's system choice. If user demand for a manual toggle emerges during dogfood, add it.

**Approach:** Selective redesign, not strict inversion. Key adaptations:
- Canvas warms slightly in dark mode (#1C1917 not pure black)
- Accent lightens for readability (#2EAA8E in dark vs #0D7C66 in light)
- Shadows are replaced by subtle border emphasis in dark mode (shadows don't read well on dark surfaces)
- Primitive border colors lighten proportionally to maintain scannability

Dark mode token overrides are included in all color palette tables above.

## 9. Production Notes

**Font loading:**
- Inter: Load via `@font-face` with `font-display: swap`. Subset to Latin. Weights: 400, 500, 600. Host locally — no external CDN dependency (aligns with local-first principle).
- JetBrains Mono: Same approach. Weight: 400, 500. Subset to Latin + common programming ligatures.
- System font fallback stack ensures instant text rendering before web fonts load.

**CSS approach:**
- Tailwind CSS with custom theme overrides in `tailwind.config.ts` — design tokens mapped to Tailwind utilities.
- CSS custom properties for all color tokens in `:root` and `@media (prefers-color-scheme: dark)` — enables runtime dark mode switching.
- shadcn/ui for standard interactive components (buttons, dialogs, inputs, toasts) — themed with our tokens.
- Primitive components (Decision, Thread, Timeline blocks) are custom-built using Tailwind utilities + CSS custom properties.

**Graceful degradation (design implications):**
- The artifact is a .md file. When opened in any Markdown renderer (VS Code, Obsidian, GitHub, a plain text editor), the primitives degrade to:
  - Decisions → blockquotes with "**Decision:**" prefix
  - Threads → blockquotes with "**Thread:**" prefix and contributor names
  - Timeline → ordered list with dates
  - Snapshots → Markdown image links
- The web companion adds the left-border styling, color coding, and interactive features. But the Markdown is always readable without it.
- Test every design decision against: "Does this work as plain Markdown?" If the answer is no, the information architecture needs to change, not the Markdown.

**Key gotchas:**
- `ink-primary` in light mode (#1C1917) is deliberately not pure black — ensure text rendering respects this warmth on all platforms
- Accent color (#0D7C66) at small sizes on `canvas` (#FAFAF8) must meet WCAG AA contrast (ratio: 4.82:1 — passes AA for normal text, passes AAA for large text)
- Dark mode accent (#2EAA8E) on dark canvas (#1C1917) contrast ratio: 6.14:1 — passes AA
- Left-border primitives need consistent 3px border + 16px padding-left. If a primitive is nested inside another (thread inside a decision), indent with additional 16px but do not add a second border.
